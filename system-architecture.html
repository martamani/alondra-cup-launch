DESIGN PRINCIPLE 01
Human review is the QA layer
Claude produced fluent, on-brand drafts but introduced factual errors — wrong museum, wrong century, wrong technique. It did not self-correct.
DESIGN PRINCIPLE 02
Don't iterate live in the system of record
Asking Claude to edit Notion rows directly via API didn't hold up at scale — it introduced duplicate rows and errors. Pasting finished drafts in by hand was more reliable.
DESIGN PRINCIPLE 03
Automate what's reliable, do the rest by hand
Text-only Bluesky posting automates well. Image attachment doesn't have a clean mapping path yet, so those go up manually.

03 / Constraint

No automation to upload images

The text automation was not the hard part. Attaching a photo to an automated Bluesky post was.

ATTEMPTED · ABANDONED
Notion image property
Make.com HTTP module — "Get a file"
Bluesky module Media field — needs binary data
✕ no clean mapping from a Notion field
Added complexity for one field, on a project already running lean. Not worth it.
→
SIMPLIFIED · SAME OUTCOME
Make.com posts text automatically
Marta attaches the photo in the Bluesky app
✓ published, with images, same day
A thirty-second manual step beats a fragile automation for one field. The right tradeoff for this volume.
